# specraft Claude Code plugin

Connects Claude Code sessions to a specraft server: spec context in, session summaries out, with hard stop gates in between.

## Contents

- `.claude-plugin/plugin.json` — standard plugin manifest.
- `.mcp.json` — registers the `specraft` MCP server (`node ${CLAUDE_PLUGIN_ROOT}/proxy/cli.js`) exposing `specraft_status`, `specraft_query`, `specraft_ingest`, `specraft_defer`, the read tools (`specraft_read_page`/`specraft_tree`/`specraft_history`/`specraft_conflicts`/`specraft_context`), and `specraft_analyze` (drift-review material: changed files + related wiki pages + open questions).
- `proxy/cli.js` — committed single-file bundle of `@specraft/mcp-proxy` (regenerated by `pnpm build`; do not edit by hand).
- `hooks/hooks.json` — hook wiring:
  - `SessionStart` (`startup|resume|clear`) → `hooks/session-start.js` injects specraft project context.
  - `SessionStart` (`compact`) → `hooks/post-compact.js` re-injects context after compaction.
  - `UserPromptSubmit` → `hooks/user-prompt-submit.js` adds prompt-time guidance.
  - `PreToolUse` (`Edit|Write|MultiEdit`) → `hooks/pre-tool-use.js` warns (without blocking) when the current branch is locked on the server; status is cached for 5 minutes (`~/.specraft/status-cache`), fail-open.
  - `PostToolUse` (`Edit|Write|MultiEdit`) → `hooks/post-tool-use.js` points at spec wiki pages related to the edited file (paths only); throttled to once per file per 10 minutes (`~/.specraft/ptu-cache`), fail-open.
  - `Stop` → `hooks/stop.js` enforces the stop gate: dirty worktree, unpushed HEAD, or missing ingest marker blocks ending a write session.
- `commands/` — slash commands: `/specraft-setup`, `/specraft-init`, and the spec lifecycle trio `/specraft-spec` (idea → structured spec), `/specraft-clarify` (resolve open questions), `/specraft-tasks` (spec → task breakdown). All lifecycle output lives in the wiki via `specraft_ingest` — no repo files.
- `agents/specraft-librarian.md` — read-only subagent that answers spec wiki questions (query/read_page/tree/history) without polluting the main session.
- `SKILL.md` — usage guidance for the model.

## Steering

The wiki page `steering.md` is the project's standing-rules page: durable working agreements (conventions, decision principles, review rules) that should shape every session. The specraft backend automatically includes `steering.md` in the context it injects at session start, so rules recorded there reach every agent without repo files. Record or update it via `specraft_ingest` (e.g. `area: "steering"`); `/specraft-spec` reads it before drafting new specs.

## Install

From the repo-root marketplace (`.claude-plugin/marketplace.json`):

```
/plugin marketplace add soyesenna/specraft
/plugin install specraft@specraft
```

Or load directly for development: `claude --plugin-dir ./plugins/claude-code`.

## Configuration

- `.specraft.json` in the project root: `server_url`, `strict_mode`.
- API key resolution: `SPECRAFT_API_KEY` env → plugin userConfig (`CLAUDE_PLUGIN_OPTION_API_KEY`, stored in the system keychain) → `~/.specraft/credentials` (dotenv-style `KEY=VALUE`, mode `0600`).
- Server URL resolution: `SPECRAFT_SERVER_URL` env → `.specraft.json` → `~/.specraft/credentials` → `http://127.0.0.1:4311`.
- TLS: a non-localhost `http://` server URL is rejected by default — use `https://` or set `SPECRAFT_ALLOW_INSECURE_HTTP=1` to bypass explicitly. Loopback (`127.0.0.1`/`localhost`/`[::1]`) stays allowed.
